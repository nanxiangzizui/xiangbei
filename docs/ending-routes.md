## 1. 边界与红线

### 1.1 保留

- 七章顺序、历史终点、湘江必败 / 遵义必开 / 泸定必夺 / 到吴起，全部不改。
- 单一历史结局；分的是人物命运与谁走到吴起。
- 五张精神卡、7 张史实图鉴、点名、104→19 的数字、20 分钟验收。
- 失败不弹 Game Over、不重开、不评分；死亡用“名字被划掉”和留白。

### 1.2 不做

- 不做好感度、攻略角色、影响游玩的路线锁、真结局、结局完成度百分比、分支存档树；v1.5 的「剧情分支」只是只读收纳与回看，已抵达 N/11 是记录，不解锁新剧情、路线或奖励。
- 不做角色选择、战斗、养成、商店、升级三选一、BOSS、排行榜、多人。
- 不做“最优/次优/成就”；“革命的情谊”只保留事件文本，不再是成就。
- 名册回廊只记“应到/未到/代答”，不做百分比、不做奖杯。

### 1.3 历史红线

- 真实人物不进剧情对白；林先生、老周、灶王、飞毛腿、冬生、细妹、何指导员、张老幺均为虚构。

- 草地断粮、收容队、担架等细节按回忆录口径写；新增文本不引新“史实”，不碰 `docs/sources.md`。

## 2. 状态

### 2.1 五档

| 值 | 显示 | 含义 |
|---:|---|---|
| 4 | 优秀 | 还能替别人背东西 |
| 3 | 良好 | 初始状态；能自己走 |
| 2 | 勉强 | 走得动，但跟不上队伍 |
| 1 | 差 | 需要物资或别人拉一把，否则走不出去 |
| 0 | 0 | 立即死亡（5/11 例外） |

- 只显示文字，不显示 0–4，不显示百分比条。
- “我”的状态显示在左上角章节名下方；状态变化时用文字 + 颜色，不闪烁。
- “一直优秀”按**最终结算时状态为 4**判定，不是每一秒都必须 4。

### 2.2 状态变化

按固定顺序结算：

1. 初始 3。
2. 每次成功救人，按“救人当时的门板状态”扣状态。
3. 救满第三人时若状态已是 1：有门板 → 当场 +1 到 2（三人援助），写 `help.used/memory.help/memory.help_door`；无门板此时通常仍是 2，不触发。
4. 草地结束 -1。
5. 结算后状态 1：若 `rescues===3 && help.used===false` → +1 到 2（无门板路径的援助，`memory.help`）；否则弹补给警告。
6. 状态 0 → 死亡；若满足 5/11 走 5/11，否则 11/11。
7. 状态 1 弹 `#danger-modal`：同意开物资栏；拒绝 / 没有可用物资 → 死亡；5/11 或 11/11。
8. 状态补到 2–4 后、门板结算前：若门板仍在身上、`rescues<=1`、当前仍带不动门板，弹“草地尽头”物资窗；只列能把状态补到 4 的配方。补到 4 则保留门板；关闭或补不到 4 则按门板条件判 `grass`。该窗口只对 `rescues<=1` 开放，救 2/3 人的路径不能靠补状态绕过质量/人数条件。
9. 门板条件与结局。

救人扣状态：

| 出发是否带门板 | 救第 1 人 | 救第 2 人 | 救第 3 人 |
|---|---|---|---|
| 无门板 | 不变 | -1 | 不变 |
| 有门板（含本次用门板救） | 不变 | -1 | 再 -1 |

- 用门板救飞毛腿时，门板在救人的那一刻算“有门板”，但第 1 人本来就不扣。
- 救 3 人、有门板：3 → 3 → 2 → 1；第三人当场帮助 → 2；草地 -1 → 1；补给 → 活，拒绝 → 5/11。
- 救 3 人、无门板：3 → 3 → 2 → 2；草地 -1 → 1；结算时三人帮助 → 2；活着，走 9/11 或 10/11。
- 救 2 人、有门板：3 → 3 → 2；草地 -1 → 1；没有三人帮助（未救满 3）；补给警告，拒绝 / 补不上 → 11/11。

### 2.3 三人帮助

- 条件：`rescues === 3`、`help.used === false`、当前状态为 1。
- 效果：状态 +1 到 2；`help.used = true`；只触发一次；状态 0 时无效。
- 有门板：在第三人救下的那一刻（`setFlag`）触发，差 → 勉强；写 `memory.help_door`，演 `g026h–g026m`（飞毛腿、冬生、灶王各伸一只手）。
- 无门板：草地结算 -1 后仍为差时（`settleGrass`）触发；写 `memory.help`，演 `g028h–g028j`（“我的脚没有沾地”）。
- 有板路径帮助后，草地 -1 会再次到差，此时弹补给警告；这是“救满三人”的必经取舍，不是bug。
- 帮助文本不再是一句旁白：有板 5 句、无板 3 句，三人各有一个动作/一句台词。

### 2.4 草地尽头的门板补给窗（2026-11-09）

- 背景：草地固定 -1 发生在门板结算之前；`rescues<=1` 时只有最终状态 4 才能带板，因此旧实现里 1/11 数学上不可达。修复不是放宽 1/11 条件，而是在扣状态之后、`settleDoor` 之前给一次明确的最后一搏。
- 触发条件（全部满足）：`condition > 1`、人未死、`had.door`、`doorOutcome === "carried"`、`rescues <= 1`、`doorCanCarry` 仍为 false、且至少有一个配方能把状态补到 4。
- 窗口：复用 `#pack-panel` 的 `door` 模式，标题“草地尽头”；只列 `delta >= 4 - condition` 的配方，补不到 4 的组合不显示，避免“用了物资仍然丢板”的假希望。
- 结算：用到 4 → 保留 `carried`，进入吴起带板路线；关闭“不补了，继续”、或配方不足 → `settleGrass` 后的门板条件照旧判 `grass`；状态 1 的 `danger-modal` 先走，不会和本窗口叠成一个连弹。
- 限制：只对 `rescues<=1` 开放。救 2/3 人的玩家仍按原质量/人数条件走 3/11、4/11，不能用补给窗绕过。
- 刷新/读档：停在 `g027a` 且满足条件时重新开窗；不写额外 pending 标记，避免二次扣状态或重复消耗。
- p024 文案提示“留一件能在草地尽头把状态补回优秀的物资”，但不强制；用掉最后一件物资仍是玩家自己的取舍。
- 证据：`project/tools/_pw-step11.js --case=doorsupply` 44/44（`docs/evidence/step-11/doorsupply-e2e`）；成功路径 `condition 3 + 锅` → 窗 → 优秀 → `doorOutcome=carried`，随后不再注入节点，连续实走 g028b→终章→吴起 w001–w040→w041→结局 1/11（点名 7、五卡 5、快照 `door_excellent`）；反例 `condition 3 + 无可用配方` → 舍弃门板 → 2/11；刷新与旧档路径同测。

## 3. 物资

### 3.1 行囊

- 行囊 **4 格 = 8 个半格单位**；所有物资总占格 ≤4。
- 初始 p024 五件各一件；不做同种多份。
- 门板单独占 2 格（4 单位），在物资栏始终“不可使用”。
- 花名册/铅笔 0 格，是剧情基座。
- 旧档超过 4 格不裁剪；显示 `used/max(4,used)`，避免旧档白屏。

| 物资 | 占格 | 半格 | 用途 | 备注 |
|---|---:|---:|---|---|
| 药 | 0.5 | 1 | 救飞毛腿；与青稞/冬生青稞组合 | 消耗品 |
| 青稞 | 0.5 | 1 | 救灶王；与药/冬生青稞组合 | 消耗品 |
| 布鞋 | 1 | 2 | 救冬生；自己用 +1 | 消耗品 |
| 铁锅 | 2 | 4 | 救灶王；自己用 +2 | 消耗品 |
| 雨布 | 2 | 4 | 救冬生；草地自己用 +1 | 物资栏只在草地可用；剧情遮雨不算使用 |
| 门板 | 2 | 4 | 铺桥/挡桥/床板/写字 | 物资栏始终不可用 |

### 3.2 使用规则

- 物资栏随时可开；**限时选项进行期间禁止打开**；选项结算后、状态变化时再弹。
- 其他物资在状态 **良好及以下** 可用；优秀时禁用，按钮写“状态已足够”。
- 门板：始终禁用，写“门板不能为自己使用”。
- 雨布：非草地章节禁用，写“只能在草地使用”。
- 单份青稞/单份药不能单独为自己使用；按钮写“需要与……同用”，不能静默失效。
- 组合配方：

| 组合 | 效果 | 备注 |
|---|---:|---|
| 药 + 青稞 | +1 | 两份都消耗 |
| 青稞 + 冬生赠青稞 | +2 | 两份都消耗；3/11 的关键 |
| 药 + 冬生赠青稞 | +1 | 两份都消耗 |
| 布鞋 | +1 | 消耗 |
| 雨布（仅草地） | +1 | 消耗 |
| 铁锅 | +2 | 消耗 |
| 门板 | — | 不可为自己使用 |

- 冬生获救后赠一份青稞：不占行囊，存 `inventory.giftBarley=true`；只能当场使用，或与自己的青稞/药组合；剧情必须写 `g026y`。
- 开局（p024 后）弹“出发前”面板：“你当前的状态为良好，是否使用物资将状态提升至优秀？”关闭不惩罚；使用只是“有机会”触发 1/11，不是保证。

## 5. 门板

### 5.1 去向

`doorOutcome` 六值：

| 值 | 含义 | item.door |
|---|---|---|
| `none` | 出发没带板 | false |
| `carried` | 当前背着 | true |
| `bridge` | 留在桥上：湘江 x025a C 横在桥头，或泸定 l019 A 铺桥 | false |
| `grass` | 草地舍弃，留在草地 | false |
| `wuqi` | 到吴起后留在墙边（w013 A） | false |
| `others` | 5/11 我死，门板由别人带到吴起 | false |

`doorCarried = had.door && (item.door || doorOutcome==="wuqi" || doorOutcome==="others")`。

### 5.2 带出条件（并列，任一）

- **A**：最终状态 = 优秀（4）。
- **B**：算上我共 4 人存活（`rescues===3`），且至少 1 名被救者状态良好（3）。
- **C**：算上我共 3 人存活（`rescues===2`），且 2 人状态良好（我可计入）。

说明：死亡者不计入存活；4 人 = 我 + 3 名被救者，3 人 = 我 + 2 名被救者。救 1 人只能靠 A；救 0 人只能靠 A。

### 5.3 草地判定

- 5/11 例外：救 3 人、出发带门板、我死在草地，且门板仍在身上（或已结算成 `others`）→ 门板由他人带到吴起，`doorOutcome="others"`，不弹舍弃。湘江 C 已把门板留在浮桥的，不算 5/11，走坏结局。
- 其余：若 `had.door && !doorCarried && doorOutcome!=="bridge"`，弹“必须舍弃门板”；点击后 `doorOutcome="grass"`、`item.door=false`，继续。
- 已留在桥上（`bridge`，湘江 C 或泸定 A）不弹舍弃；结局标题仍按该路线（“门落无声”或“板留人渡”），短描述换桥头版本：“门板留在了桥头。你到了吴起，后来的人从它撑住的地方走了过去。”
- 满足 A/B/C 则保留门板；不满足则舍弃。
- 舍弃弹窗文案：“由于你体力透支，或帮手不足，无法将门板带到终点，你必须舍弃。”按钮“舍弃门板”。

### 6.1 边界收束

- 1/11 的设计主例是“0 人获救 + 一直优秀”；实现按“带出 + 最终优秀 + 救≤1”收束。草地固定 -1 后，1/11 会在门板结算前得到一次“草地尽头”补给窗：只有把状态补回 4 才能继续背板；这是 1/11 从“数学上不可达”恢复为可达的关键。救 1 人且最终优秀也归 1/11，文案不写“0 人”，避免出现第 6 种门板路线。
- 3/11 的设计主例是“救 2 人 + 带板 + 条件 C”；救 3 人但活着且满足 B 也归 3/11，文案不写“2 人”。
- 2/11 与 4/11 都是“门板没带出”，按救人数分。`doorOutcome==="bridge"`（湘江 C 或泸定 A）时短描述写“门板留在了桥头。你到了吴起，后来的人从它撑住的地方走了过去。”；`grass` 时写“门板留在了草地。你到了吴起，带着几个人，也带着它留下的那一点重量。”。标题不因桥/草地把“门落无声/板留人渡”改成“桥板”。
- 1/11 救 0 时写“背来的是一扇门，不是一路的人”；救 1 时点名唯一活下来的人。3/11 保留“至少还有几个名字”，实际姓名由命运句写；7/11 同样保留“至少还有一个名字”，姓名由命运句写。6/8/9/10 的短描述只写人数，不写具体是谁；姓名由结局页动态命运句补足（见 §9.6）。
- 5/11 是唯一“我死、门板仍到吴起”的路线；`doorOutcome="others"`，8 名（含满崽），companyEnd 18，林先生 absent。湘江 C 已把门板留在浮桥的，即使救 3 人死在草地，门板也不在吴起，走 11/11 坏结局。
- 坏结局不走吴起点名：`names=[]`，companyEnd 18，ending 页显示“名册没有翻到吴起”；五卡仍渲染，按条件亮/灰。
- 没有“全活”；没有“救 3 且带板且活着”。

### 6.2 3/11 可达性示例

配置：门板 2 + 药 0.5 + 布鞋 1 + 青稞 0.5 = 4 格。

1. 飞毛腿用药（药消耗，救 1，状态 3）。

## 14. 决策表 D1–D15

| 编号 | 决策 | 理由 |
|---|---|---|
| D1 | 状态用 0–4 整数；初始 3；最终 4 才算“一直优秀” | 只用有限档位，避免百分比；结局 A 用最终值，避免“每一秒”无法实现 |
| D2 | 行囊 4 格 = 8 个半格单位，内部用整数 | 0.5 格用浮点会累积误差；UI 显示 3.5/4 |
| D3 | 初始五件各一件，不做同种多份；冬生赠青稞单独标记 | 设计稿没有重复购买/叠加；赠品不占格，不能与普通青稞混存 |
| D4 | 配方严格按设计稿；单青稞/单药不能单独自用 | 避免“有药就永远能回血”；组合需要取舍 |
| D5 | 救人惩罚按“救人当时的门板状态”算，含本次用门板 | 用门板救人本身就是带板负担；顺序不影响结果 |
| D6 | 三人帮助在救满 3 人、状态为 1 时自动触发一次；有板当场、无板草地结算；0 无效 | 帮助是“有人拉你一把”，不是复活；只一次；有板路径之后仍要面对一次补给警告 |
| D7 | 差状态弹警告窗：同意开物资栏，拒绝/不用判死；0 不弹窗 | 差状态必须让玩家看见代价并明确取舍；5/11 仍由 settleDoor 收口 |
