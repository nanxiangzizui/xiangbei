> 2026-11-08 用户确认：①锁定卡只写“未解锁”，不写选项和原因；②金沙江记名（j018）也做成 2 条成就。
> 本文是成就系统的规格与 48 条词条总表。代码实现后，以本文与 `story.js` 的数据一致性检查为准。

## 1. 范围

- 成就入口三处：标题菜单、暂停菜单、结局页（结局页只列本局词条）。
- 成就对象：全部 `choice` / `multichoice` 节点的每个选项，加上金沙江 `j018` 记名的两个结果。
- 19 个 choice/multichoice 节点共 50 个节点级选项；按叙事选择组去重为 **17 组 46 条**；再加 `j018` 的 2 条，共 **48 条**。
- `x025a/x025b` 是同一选择的有板/无板变体，共用 A/B/C；`l019/l019x` 共用 bridge/medicine/leave。它们不重复计数。
- `w026` 点名是 `interact` 的自动流程，不是玩家选项，不设成就。
- 不做：成就点数、百分比、全收集奖励、好感度、真结局、分支存档树；不改 11 条人物结局与五张精神卡。
- 解锁不弹大窗、不新增音效、不打断阅读；暂停与结局可见。打开成就窗口复用现有 `codex` cue 与 duck。

## 3. 数据结构

`story.js` 顶层新增 `XB.story.achievements`。choice 条目：

    {
      id: "p021-A",
      chapter: "prologue",
      decision: "p021",
      key: "A",
      title: "门板在背"
    }

interact 条目：

    {
      id: "j018-done",
      chapter: "jinsha",
      kind: "interact",
      decision: "j018",
      outcome: "done",
      title: "记下名字"
    }

- `kind` 缺省为 `choice`；只有 `j018` 两条写 `interact`。
- `key` 用 `branchMap.decisions[decision].options` 的键，不用节点级 A/B/C（l019/l019x 由 `optionKeys` 归一）。
- 标题只允许汉字/数字/字母，长度按 Unicode 码点计，1–8；本项目实际 3–5。
- 不复制选项文字与后果文案：描述生成时从原节点读选项文字，从 `branchMap` 读后果。

## 4. 描述生成

### 4.1 choice / multichoice

模板：

    在「{章标题}」的「{决策组标题}」选择中，你选择了「{选项文字}」。
    {branchMap.decisions[decision].options[key]}
    因此，你解锁了「{词条}」。

例（p021 A）：

    在「序章 · 于都」的「门板」选择中，你选择了「带上这块门板」。
    你带上了门板。行囊只剩两格，多背三十斤；往后每过一次险，你都要先替这块板子找一条路。
    因此，你解锁了「门板在背」。

- 多选每个选中项各生成一条；`p024` 的 `homepot` 文字取节点选项“铁锅”，后果取 `branchMap` 的 `homepot`。
- 超时：把第一行改为“时间到了，默认项「{选项文字}」替你做了决定。”；其余相同。`timedOut` 写进成就档元数据；首次解锁后不覆盖。
- 条件选项未满足时不渲染为可选，也不可能解锁；不另写“未达成”成就。

### 4.2 interact（j018）

done：

    在「第三章 · 金沙江」的「记名」中，你蹲了半夜，把「张老幺」的名字抄在名册的边角上。
    你抄下了张老幺的名字。名字写在名册的边角上，墨还没干。
    因此，你解锁了「记下名字」。

skip：

    在「第三章 · 金沙江」的「记名」中，你蹲了半夜，没有动笔。
    你蹲了半夜，一个字没写。第二天开船，你连他姓什么都想不起来了。
    因此，你解锁了「没有动笔」。

- 记名限时 8 秒；超时走 skip，成就档 `timedOut: true`，描述首行写“时间到了，你一个字没写。”
- 点“跳过”也解锁 skip；两者共用“没有动笔”。

### 4.3 锁定态

- 卡片灰框 + 词条名 + “未解锁”。
- 点开只显示：“这个成就还没有解锁。继续往前走，做完那个选择，就会记下来。”
- **不显示选项文字、决策组标题、后果、解锁时间**，避免提前泄露后面章节。

## 5. 存档

### 5.1 独立成就档

键：`xiangbei.achievements.v1`

    {
      "version": 1,
      "updatedAt": 1762531200000,
      "unlocked": {
        "p021-A": { "at": 1762531200000, "timedOut": false },
        "j018-skip": { "at": 1762531260000, "timedOut": true }
      }
    }

- 只接受 48 个已知 id；未知 id 丢弃；`at` 是首次解锁的 epoch ms；`timedOut` 只记首次。
- 读失败/坏 JSON：备份为 `xiangbei.achievements.v1.bad`，回内存空档；不白屏。
- 写失败：保留内存态，提示“本机无法保存成就”；不打断剧情。
- 与 `xiangbei.save.v2`、`xiangbei.roster.v1`、`xiangbei.branches.v1` 分离；清主档不清成就。
- 不新增主档顶层键，`PERSIST_KEYS` 仍为 11；不升 `SAVE_VERSION`。

### 5.2 本局快照

- `ending.achievements` 可选数组，存本局词条 id（去重，按选择发生顺序 + j018）。
- `normalizeEnding` 允许该键；旧档没有就不补，结局页显示“旧档未记录本局成就”。
- `finishChapter` 在 `state.choices = []` 之前收集；之后从 `state.choices` 已取不到。
- `j018` 不在 `choices` 日志里：新增 `memory.namepick_done`（pick/skip 都置 true）与既有 `memory.zhang`（抄了张老幺才 true）区分 done/skip。
- 旧档若已有 `memory.zhang: true`，本局收集时按 done 处理；旧档没有 `namepick_done` 的 skip 不补记（只在结局说明旧档限制）。

## 6. 解锁点

- 单选：`resolveChoice` 在 `applyChoice` 成功后立即解锁所选 key 的成就；超时同样解锁，`timedOut: true`。
- 多选：`resolveMultiChoice` 在 `applyMultiChoice` 成功后按 `result.selected` 逐项解锁。
- 记名：`pickName` 解锁 `j018-done`；`skipNamepick`（按钮或 8 秒超时）解锁 `j018-skip`。
- 结局兜底：`finishChapter` 先 `collectRunAchievements(state)`，逐条补写成就档，再写 `ending.achievements`。
- 重进已结算结局：`choices` 已清空，但 `flags.memory.zhang` 仍会产出 `j018-done`；此时必须把快照 `previous.achievements` 合并回来，否则结局页从 22 条掉成 1 条（2026-11-08 实测并修复）。
- 旧档中途继续：进入游戏/打开成就窗口时可按 `choices` 与本局旗标计算“本局”；成就档只在选择提交、记名提交或结算兜底时写，不在读档时批量写。

- 标题菜单第 6 项“解锁成就”；后四个入口改为 2×2，保持四行，不挤掉制作名单。

- 结局页词条 chips 点击 → 打开同一成就面板并直接展开该条详情。

### 7.2 成就窗口
