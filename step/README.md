# step/ —— 分步执行计划（过程文档）

> 这里放**每一步怎么做的执行计划**，不是项目状态源。
> 范围与排期看 `向北-项目计划书.md`；当前进度与步骤状态只看 `.claude/CLAUDE.md`；细节设定看 `docs/`。
> 冲突时：用户最新明确指令 > 计划书 > `CLAUDE.md` > `docs/` > 本目录。

## 每个计划文件的固定骨架

1. 元信息（所属步骤、对应计划书条目、当前状态、时间盒、出口，出口逐字引用 `CLAUDE.md`）
2. 起点盘点（已有资产 / 缺口）
3. 不变量（本步骤不许动的东西）
4. 产出清单（文件级：路径 / 新建或修改 / 内容 / 验收 / 下游消费者）
5. 任务卡（T0.0、T0.1……每张含 目的 / 输入 / 动作 / 产出 / 完成判据 / 常见坑）
6. 时间盒（标准版 + 压缩版）
7. 验收清单（可勾选，逐条映射出口）
8. 风险与返工触发条件
9. 禁区（本步骤不要做的事）
10. 交接接口（下游模块从本步骤拿什么）
11. 复核记录（执行时回填：日期 / 证据 / 结论）

## 约定

- 计划里出现的数字（字数、秒数、容量、船数）必须能在 `docs/` 或计划书里找到同名数字；找不到就先改 `docs/`，再写进计划。
- 任务卡编号用 `T<步骤号>.<序号>`（如 `T0.6`），验收用例沿用 `docs/test-cases.md` 的 `T01–T20`，两套编号不要混用。
- 证据分级沿用项目口径：A 浏览器实测 / B 代码完成未跑 / C 设计稿口述 / D 未验证。文本类步骤（零）通常只能产出「文本证据」（字数统计、红线检索输出、复核记录），**不得写成"章节可玩"**。
- 计划落地后，长期口径以落地文件为准（如剧本格式落在 `docs/script/README.md` 后，以该文件为准，本目录的计划不再改模板），避免同一规则两处维护。
- 每一步完成后：更新 `.claude/CLAUDE.md` 步骤表 → 提交 → 打 tag（如 `step-0-done`）。
