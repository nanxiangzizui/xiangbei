## 4. 设计决策

### P1 记录只有一个主文件

- docs/test-record.md 是唯一“结果”文件；docs/evidence/step-07/run-log.md 只放过程与环境细节，截图/JSON/ZIP 只做附件。
- 记录用表格优先，目标 ≤180 行；长日志、逐条控制台输出放证据目录，不粘进记录。
- 理由：评审和步骤八只需要一页能看懂“过没过、例外是什么、下一步做什么”；过程细节不应淹没结论。

### P2 用例分层，不重写已有 38 条

- T01–T38 是主回归集；本步只补 T39–T51，覆盖浏览器、分辨率、真机、离线、隐私、音频、外部试玩、外读、性能、可访问性。
- 原有 P0 用例全部保留；不为“步骤七”改旧用例的通过标准。
- 新用例编号连续、场景不重复；每条有优先级、操作、预期、证据。
- 理由：旧用例已经绑定功能和步骤五/六的验收，重写会造成历史证据失真。

### P3 浏览器结论必须分“真实/代理/未验证”

- Edge：系统安装路径启动，版本以 browser.version() 为准。
- Chrome：优先安装 stable；装不上时可用 Playwright Chromium 做功能冒烟，但记录必须写“Chromium，不是 Chrome”。
- Safari：只在 macOS/iOS 真机运行后写“Safari 通过”；Windows 无 Safari。WebKit 只能写“WebKit 代理冒烟”，不能写 Safari 通过。
- 任何“未执行”都保留在记录里，不用“应该没问题”替代。
- 理由：这是交差材料里最容易被质疑的部分；诚实的分级比虚假的三浏览器全绿更有价值。

### P4 测试脚本只做测试工具

- 新建 project/tools/_pw-step7.js，使用 playwright-core；参数至少支持 --browser=edge|chrome|webkit、--url=file|http、--case=T39…、--out=docs/evidence/step-07。
- 脚本从 my-playwright-project/node_modules 或环境变量 PW_CORE 解析依赖；不再硬编码 C:\Users\...\Temp\...。
- 不新增 package.json 到 project/，不把 node_modules 放进仓库或 ZIP；不把测试代码打进 index.html。
- 脚本失败必须非零退出；不能用 try/catch 吞掉断言。
- 理由：测试依赖必须可复现，但不能污染六文件运行时。

### P5 测试数据隔离，不用调试跳章冒充全流程

- 每条自动化用新 browser context、空 storageState；file:// 与 http 分开跑。
- 全流程从标题开始，真实点击/键盘推进；?reset=1 只在开始前清档；?chapter= 只用于单章定位，不能作为“全流程通过”的证据。
- 4 个单关用 ?minigame= 独立跑失败/成功路径；全流程至少完整跑一遍四关与结局。
- 截图前隐藏 debug，不把 debug 面板当游戏 UI；需要 debug 数值时另存日志。
- 不读写试玩者的真实 localStorage；外部试玩用独立浏览器配置文件。
- 理由：调试跳章不会补章末记忆，容易造出“结局能开、五卡不对”的假通过。

### P6 20 分钟用真人墙钟，不用脚本快进

- 计时从标题稳定可见（可点击“开始”）到 ending 五卡与七人名单稳定显示；包含片头/章节卡/小游戏/结算/图鉴浏览；不含暂停。
- 每次开始前清档；同一轮中途暂停或被打断则作废重跑；不按“跳过已读”计时。
- 三次分别覆盖：正常首玩、慢读、外部玩家自由玩；记录选择路径、是否开图鉴、设备、浏览器。
- 验收取三次最大值；三次都必须 ≤20:00；记录中位数只作参考。
- 计时用可见秒表/录屏时间戳；自动化测试的耗时不能替代真人计时。
- 理由：19:44 的预算是按字数与目标操作估的，真实阅读、图鉴和鼠标/触摸误差只能实测。

### P7 裁剪有顺序、有闸门、有回滚

- 顺序严格按计划书/CLAUDE：草地 → 金沙江 → 遵义改纯对话；保留序章/湘江/泸定/点名。
- 前两刀只裁对话/节奏，不删小游戏、不删 7 张图鉴、不删五卡条件、不改存档。
- 第三刀会动遵义错误卡与 truth 五卡，必须先向用户说明并得到确认；不得在测试记录里悄悄改设计。
- 每刀后同步 docs/script、story.js、count-words、story-bible、test-cases、check-build/smoke；重新跑全流程与三次计时。
- 任何一刀导致 4 关/7 注/5 卡/点名缺失，立即回滚该刀。
- 理由：20 分钟是硬线，但“删到能过”会破坏主题机制；裁剪必须有可审计的边界。

### P8 移动端以实际 CSS 像素验收，不以逻辑像素自欺

- 844×390 下舞台约 693×390，缩放约 0.542；逻辑 26px 正文约 14.1 CSS px，是正文下限的来源。
- 暂停按钮从 48 逻辑改为移动端 96 逻辑（约 52 CSS px）；小游戏热区沿用 96 逻辑；高频按钮（继续、选项、图鉴关闭、结局按钮）逐个量 getBoundingClientRect。
- ending 在移动端不再使用 880×560 面板缩放；改为接近全舞台的可滚动面板（建议逻辑 left 24/top 24/width 1232/height 672，实施前先写 ui-layout），正文/卡句/姓名 ≥26 逻辑，辅助标签可 20–22 逻辑但要记录例外。
- 验收看实际 CSS px 与可点击性，不只看 1280 截图。
- 理由：B16 和 T29 已经证明“逻辑尺寸看起来对、物理上太小”是本项目真实风险。

### P9 外部试玩是体验证据，不是找夸奖

- 3 位同学，至少 1 位不常玩游戏；不提前讲剧情、不教操作、不替他们做选择。
- 观察并记录：第一次卡住的位置、是否知道下一步点哪里、哪句话让他停、是否愿意继续、最后记住了谁。
- 每人结束后问 5 个固定问题；原话可引用但匿名；录像/录音需先征得同意，不录人脸。
- 另找 1 位做剧本外读（可与试玩者重叠），读完三场重头戏后回答理解问题；这是步骤零欠账，不是可选项。
- 不用 AI 读者、作者自评或“朋友说不错”替代原始记录。
- 理由：项目目标是 20 分钟情感体验；自动化只能证明流程通，证明不了卡点和泪点。

### P10 音频用“听到/没听到/无法判断”三态

- 首次手势前 locked、无 AudioContext；点击后 ready，有环境床；不自动播放。
- 9 床 × 17 场景映射抽测；12 cue 至少覆盖门板、弃物、渡船、攀索、选项、结局；同时 activeBeds≤2。
- 扬声器与耳机各听一次，记录设备、音量、是否刺耳/爆音/盖文字；headless peak=0 只能写“未捕获”，不能写“无爆音通过”。
- 真实切标签、手机锁屏、回来 resume；暂停/图鉴 duck 0.3/0.45；静音/音量刷新保留。
- 理由：声音是主观验收，必须把客观读数与主观结论分开。

### P11 证据可追溯、仓库干净

- 命名：T39-edge-1280-full.png、T41-chrome-1920.png、T44-offline-file.png、T47-participant-A.md；不要用 final、new、test1 这类无法追溯的名字。
- 截图只截游戏区域；不含浏览器账号、桌面通知、真实姓名；视频不提交。
- docs/evidence/step-07/ 整个目录 gitignored；临时 ZIP 放该目录，测试后删除或保留在本地。
- 记录里写相对路径和生成命令；不写“见桌面”。
- 理由：步骤八要复用证据，评审要能复核；大文件不能进仓库。

### P12 完成门槛与发布门槛分开

- 步骤七可以“有条件完成”：P0 全过，或 P0 例外经用户明确接受，并在记录里写影响与补救。
- 存在 S1 blocker（白屏、无法通关、存档损坏、四关/七注/五卡缺失）时不得 tag。
- 步骤七完成不等于允许部署；部署/正式 ZIP/视频发布是步骤八，需用户确认。
- 记录最后必须给出三选一：可交差 / 有条件交差 / 不可交差。
- 理由：测试记录要能支持决策，而不是只写“测试完成”。

### T7.4 手机、离线、隐私、真实音频（100 / 55 分钟）

**目的**：把“模拟看起来可以”变成“真实限制下有交代”。

**输入**：T7.1 设备；T7.2 脚本；docs/audio-system；quality-bar；临时 ZIP。

**动作**：

2. 离线 ZIP：把六个运行时文件与 assets/（空）打成临时 ZIP，解压到独立目录；断网/飞行模式，打开 index.html；跑到至少序章结束与一次小游戏；断言无 fetch/XHR/外部请求、无 404、存档可用或降级提示。

6. 主观听感：扬声器与耳机各一次，记录设备、音量、是否刺耳/爆音/盖文字；headless peak 只记读数，不替代听感。
7. 真实后台：电脑切标签、手机锁屏/来电/切后台，回来 resume；暂停/图鉴 duck 0.3/0.45；不偷倒计时、不丢进度；记录“真实/模拟”。

**产出**：手机/离线/隐私/音频记录；临时 ZIP；例外清单。

**完成判据**：每项有证据或明确例外；离线无外部请求；隐私不白屏；首次手势前无声音；真实后台/听感至少各有一项真实验证（否则记 P1 例外）。

**常见坑**：把 Playwright 移动模拟当真机；用 headless peak=0 写“无爆音”；临时 ZIP 漏 CSS/JS；隐私测试把预期存储错误算成失败；锁屏测试没真正切后台；音频测试在静音状态下说“没声”。
