## 项目一句话

玩家扮演长征途中红一方面军某连的 16 岁文书，背着一块从于都老家门上锯下的木板，从于都走到吴起；通过对话、取舍和 4–5 个小游戏（核心版 4 个），决定带什么、救谁、记住谁，在 20 分钟内走完长征。

- 形态：视觉小说 + 限时抉择 + 轻量小游戏
- 七段：序章·于都 → 湘江 → 遵义 → 金沙江 → 泸定 → 草地 → 终章·吴起·点名
- 五条精神：理想信念、不怕牺牲、独立自主实事求是、顾全大局严守纪律、依靠人民艰苦奋斗；每条对应一个可操作机制
- 交付：纯静态网页 + ZIP 离线版 + 一页设计说明 + 3 分钟演示

## 当前真实状态

**本文件不维护独立状态。** 唯一状态源是 `.claude/CLAUDE.md` 的“当前进度”与“分步骤”表；进入项目先读那里，本文件只讲怎么做、坑和验收。

## 全局硬规则（每一步都适用）

### 史实红线

- 大事件结局不可改：湘江必败、遵义必开、泸定必夺。
- 不虚构领导人对话；真实人物只进“史实注”，不进游戏剧情。遵义复盘用旁白/文件/虚构基层人物呈现，不让真实领导人开口。
- 争议细节标注“有不同说法”：X 光机具体情形、22 勇士牺牲人数、金沙江船数。
- 严格区分史实 / 回忆录 / 文学；《七根火柴》《金色的鱼钩》是小说，不能当史料。
- 每条史实注入注明出处；成稿附《史实出处表》。

### 情感尺度

- 虚构人物（含主角）在片头或图鉴明确标注“虚构人物，非史料人物”。
- 死亡用“名字被划掉”和留白表现；不做血腥特写；不消费苦难。
- 不把牺牲做成分数；小游戏失败只结算代价，不做“完美通关”评分。
- 敌人不脸谱化。

### 玩法尺度

- 每关 60–90 秒；没有 Game Over；失败不重开，只改变代价。
- 单一结局 + 可变细节（带什么、救谁、记住谁）；不做分支结局树、战斗、“打鬼子”关卡、养成、排行榜、多人。
- 选项是道德取舍，不设“明显正确”的答案；限时选项超时按默认项结算并记录代价。
- 20 分钟是硬验收；超时先裁草地，再裁金沙江，最后把遵义改成纯对话；保留序章/湘江/泸定/点名。

### 技术底线

- 剧情内联；不用 `fetch`/XHR/ES module；经典 `<script>` + 全局命名空间，保证 `file://` 离线 ZIP 可玩。
- Canvas 按 `devicePixelRatio` 放大；触摸坐标用 `getBoundingClientRect()` 换算；热区不小于 44px。
- `localStorage` 加版本号并用 try/catch；版本不匹配时迁移或提示重置，不能白屏。
- `AudioContext` 在首次用户点击后创建/恢复；静音与音量持久化。
- 字体使用前核对授权；加载失败回退系统宋体；不把未授权字体打进 ZIP。
- 所有资源用相对路径（`./`），兼容 GitHub Pages 子路径与 `file://`；不依赖任何 CDN。
- 16:9 横屏为基准；手机竖屏给出“请横屏”提示；小游戏单手可完成。

### 范围与证据

- 文本量是最大成本；先写三场重头戏，再补其他章；不要平均用力。
- 核心 4 关（+ 可选第 5 关）共用一套“限时分配”引擎（计时、拖拽、配额、疲劳、网格），不要每关写一套独立引擎。
- 证据分级：A 浏览器实测（截图/录屏/控制台）；B 代码完成未跑；C 设计稿/口述；D 未验证。没有实际运行就写“未验证”。
- 不可逆动作先确认：部署上线、覆盖线上版本、删除/重置存档格式、公开发布视频、打包他人字体/素材。

## 每次任务的固定流程

1. **对齐**：复述当前步骤、目标、要改的文件、验收判据、是否有不可逆动作。
2. **读现状**：读计划书对应段落 + 本步骤章节 + 现有代码/剧本；先复现再改。
3. **先文本/先原型**：内容没定不写正式代码；小游戏先做独立可玩原型，再接章节。
4. **小步改**：一次只改一个变量；先跑通再美化；行为等价的重构单独做。
5. **验证**：`file://` 与本地服务各开一次 → 键鼠 → 触摸 → 三档分辨率 → 刷新存档 → 控制台无报错。
6. **留证据**：截图/录屏/测试记录写进 `docs/test-record.md` 或当次汇报；失败照实写。
7. **汇报**：改了什么、证据、未验证项、风险、下一步建议。

## 步骤零：定题、史料与剧本（对应计划书 1–2）

**目标**：在写任何代码前，把“讲什么、按什么史实讲、哪些能玩”定死。文本是最大成本，先写三场重头戏。

### 0.1 七段结构表

先定一页结构表，字段至少包含：段落 / 场景 / 核心事件 / 玩法 / 史实注。

| 段落 | 场景 | 核心事件 | 玩法 | 史实注 |
|---|---|---|---|---|
| 序章 | 于都 | 出发前夜；从家门锯下门板；告别 | 门板：拖拽摆放 + 天亮倒计时 | 于都出发 |
| 第一章 | 湘江 | 渡江；辎重与牺牲；必须舍弃 | 弃物：拖拽取舍 + 渡口配额 | 湘江战役 |
| 第二章 | 遵义 | 复盘前两章的选择；纠错 | 无小游戏；错误卡 + 对话 | 遵义会议 |
| 第三章 | 金沙江 | 找船、调度、追兵 | 渡船：船次调度 + 船工疲劳 + 追兵计时 | 巧渡金沙江 |
| 第四章 | 泸定 | 攀索夺桥 | 攀索：Canvas 动作 + 22 个光点 | 飞夺泸定桥 |
| 第五章 | 草地 | 分粮、让粮、减员 | 纯对话 + 资源选择（完整版加探路/分粮） | 过草地 |
| 终章 | 吴起 | 点名；数字；五张精神卡 | 点名交互（不计入 4 关） | 到达吴起 |

结构表要能一眼看出：哪段有游戏、哪段只有对话、哪段负责情感回收。

注意：七段不是每段都有小游戏。遵义用错误卡/对话替代，终章“点名”是结局交互，不占四个核心小游戏的名额；不要把“点名”误算成第 4 关；草地核心版也只有对话/资源选择，探路/分粮是可选第 5 关。

### 0.2 五条精神 → 机制

| 精神 | 机制 | 落点 |
|---|---|---|
| 理想信念 | 门板：带什么、为什么带；门板贯穿全程，终章回收 | 序章 + 终章 |
| 不怕牺牲 | 攀索：22 个光点，每个光点对应一个名字/一份牺牲 | 泸定 |
| 独立自主、实事求是 | 遵义错误卡：把前两章的真实选择翻出来复盘 | 遵义 |
| 顾全大局、严守纪律 | 渡船：船次、配额、船工疲劳、追兵计时 | 金沙江 |
| 依靠人民、艰苦奋斗 | 草地分粮/让粮的资源选择（核心版为对话选择；完整版加探路/分粮） | 草地；民心值回接金沙江船工数 |

这是工作映射；步骤零确认后写死。机制必须可操作、可失败、可留下痕迹，不能只是弹一句口号。

### 0.3 《史实锚点表》

一页表，逐章记录：

| 章节 | 时间 | 地点 | 关键数字 | 出处 | 类型 | 游戏化处理 | 红线检查 |
|---|---|---|---|---|---|---|---|
| 序章 | 1934-10 | 于都 | 中央红军出发 | （待逐条核实并填写） | 史实 | 门板为虚构道具，出发背景为史实 | 不虚构领导人 |

要求：

- 七段各至少一条锚点；合计 7 张史实注（序章 + 五章 + 终章）。
- 类型只能写“史实 / 回忆录 / 文学”，并给出处。
- 大事件结局写进“红线检查”列：湘江必败、遵义必开、泸定必夺。
- 争议细节单列：X 光机具体情形、22 勇士牺牲人数、金沙江船数，标“有不同说法”。
- 真实人物只出现在史实注，不出现在剧情对话。
- 示例行只示格式，不代替逐条核实；不要凭记忆写出处。

### 0.4 剧本与分镜

写作顺序：

1. 先写三场重头戏：序章·于都、第一章·湘江、终章·点名。
2. 再补遵义、金沙江、泸定、草地。
3. 每章 30–50 个对话 beat、2–3 个选项、1 个小游戏规则、1 张史实注。
4. 全文控制在 4000–6000 字（叙事正文，不含 UI 文案与史实注）。

数据形状（示意，字段在步骤三定稿）：

```js
// story.js —— 经典脚本，全局命名空间；不要用 import/export
window.STORY = {
  chapters: [{
    id: 'prologue',
    title: '序章 · 于都',
    codex: { id: 'yudu', title: '于都出发', type: '史实', source: '（待填）' },
    script: [
      { type: 'line', speaker: '旁白', text: '……' },
      { type: 'choice', prompt: '……', timeout: 8, options: [
        { text: '……', set: { 'item.door': true }, cost: '……' }
      ]},
      { type: 'minigame', id: 'door', config: { duration: 75 } },
      { type: 'codex', id: 'yudu' }
    ]
  }]
};
```

写作规则：

- 剧本只写数据，不写 DOM/Canvas 代码。
- 每个选项都要有代价；不设“明显正确”的答案。
- 旗标用命名空间（`item.*`、`trust`、`memory.*`、`choice.*`），不要在脚本里散落裸布尔值。
- 死亡用划名与留白；不写血腥特写；不把牺牲写成数字游戏。
- 敌人不脸谱化；不虚构领导人台词；不把小说情节当史实。
- 门板的象征意义先定：为什么锯、一路怎么带、终章怎么回收。

### 步骤零出口

- [ ] 一页七段结构表。
- [ ] 一页《史实锚点表》，7 条史实注，出处/类型/争议标注齐全。
- [ ] 五条精神各对应一个可操作机制。
- [ ] 序章/湘江/点名三场重头戏完整；其余章有 beat 级大纲。
- [ ] 全文 4000–6000 字。
- [ ] 红线复核：大事件结局、领导人台词、争议细节、文学/史实区分。
- [ ] 虚构人物声明已写。

### 本步骤的坑

- 先写代码后补文本 → 文本成本失控。
- 七章平均用力 → 前三章和终章不够。
- 把《七根火柴》《金色的鱼钩》当史实。
- 让真实领导人在剧情里说话。
- 选项写成“正确/错误”二元。
- 门板的象征意义没定，导致终章回收无力。
- 字数把 UI 文案/史实注算进去。

## 步骤一：工程骨架（对应计划书 3）

**目标**：能跑通“标题→地图→一段对话→返回”的空壳。

### 1.1 文件职责

| 文件 | 职责 | 不要放 |
|---|---|---|
| `index.html` | 舞台、UI 层、脚本入口 | 剧情正文、复杂逻辑 |
| `style.css` | 版式、配色、组件、纸纹 | 游戏状态 |
| `engine.js` | 状态机、输入、存档、转场、音频模块 | 具体章节文本 |
| `story.js` | 七章数据、选项、旗标、史实注 | DOM/Canvas 代码 |
| `minigames.js` | 核心 4 关 + 可选第 5 关 + 共享限时分配引擎 | 章节叙事 |
| `art.js` | 程序化版画/纹理/剪影 | 交互逻辑 |

### 1.2 固定舞台

- 设计坐标固定 1280×720（16:9），舞台居中，剩余区域用纸白/墨黑留边。
- CSS 可用 `width: min(100vw, calc(100vh * 16 / 9)); aspect-ratio: 16 / 9;`，不要写死像素。
- Canvas 不要只把内部尺寸写死为 1280×720：按实际显示尺寸 × DPR 设置 `canvas.width/height`，再把 1280×720 设计坐标映射到画布；否则 1920 屏会糊。
- 指针坐标必须换算：`x = (e.clientX - rect.left) / rect.width * 1280`，`y` 同理；不要直接用 `clientX`。
- 监听 `resize`/`orientationchange`，只重算尺寸，不重置游戏状态。

### 1.3 状态机

状态固定为：`title / map / vn / choice / minigame / result / codex / ending`。

```js
const state = {
  scene: 'title',
  chapterId: null,
  scriptIndex: 0,
  flags: {},
  codex: [],          // 已解锁 id
  choices: [],        // 选择历史，供遵义错误卡使用
  settings: { textSpeed: 2, volume: 0.6, muted: false, reducedMotion: false }
};
```

- 所有切换走 `go(scene, payload)`：先 `exit` 旧场景（清定时器、解绑临时事件、停音频），再 `enter` 新场景。
- 不允许各场景自己 show/hide DOM；否则状态会打架。
- 开发期可加 `?debug=1` 跳章/查看旗标；发布前确认不剧透或隐藏入口。

### 1.4 存档

- 键名：`xiangbei.save.v1`（版本号必须进键名或字段）。
- 存档字段：`version / chapterId / scriptIndex / flags / codex / choices / settings / unlockedChapters`。
- 保存时机：进章、beat 推进、选项提交、小游戏结算、设置变更；不要每帧保存。
- 启动读取：版本匹配则恢复；不匹配则尝试迁移，失败时提示“重置存档”，不能白屏。
- `localStorage` 读写全部包 try/catch；不可用时提示“本次游玩不保存”，游戏继续可玩。
- 章节解锁按顺序；图鉴已解锁条目不要因章节回退而丢失。

### 1.5 输入路由

- 统一用 `pointerdown`（鼠标/触摸/笔），不要分别写 mouse/touch。
- 键盘：`Space`/`Enter` 推进，`Esc` 暂停，`1–3` 选项。
- 打字机：第一次输入补全当前行，第二次才推进；推进后加约 100ms 输入锁，避免双击连跳。
- 忽略 `keydown` 的 `repeat`；阻止空格滚动页面。
- 所有可点区域不小于 44×44px；手机端不依赖 hover。

### 步骤一出口

- [ ] `file://` 与 `http://localhost` 都能打开。
- [ ] 标题→地图→一段对话→返回地图。
- [ ] 对话中途刷新，存档恢复。
- [ ] 1920×1080、1366×768、手机横屏三档不出界、不裁切。
- [ ] 控制台无报错。
- [ ] 触摸点击推进正常。

### 本步骤的坑

- 用 `fetch('story.json')` → `file://` 失败。
- 用 ES module `import/export` → `file://` 可能被 CORS 拦截。
- Canvas 内部尺寸固定 1280×720 → 高分辨率屏糊。
- 触摸坐标不换算 → 点击偏移。
- 每个状态各自绑定 `document` 事件 → 重复推进/内存泄漏。
- `localStorage` 不 try/catch → 隐私模式白屏。
- 用 `setInterval` 驱动打字机/倒计时 → 后台标签页漂移；用 `requestAnimationFrame` + delta，并在 `visibilitychange` 时暂停。
- 存档每帧写入 → 卡顿。

## 步骤二：视觉系统（对应计划书 4）

**目标**：标题画面 + 一套可复用的 UI 组件库，让“纸、墨、朱砂、版画”的风格成立。

### 2.1 设计令牌

颜色（写进 `:root` CSS 变量，组件里不准散落十六进制）：

| 令牌 | 色值 | 用途 |
|---|---|---|
| 纸白 | `#E8E1D0` | 背景、纸张、留白 |
| 墨黑 | `#1A1714` | 正文、描边、剪影 |
| 朱砂 | `#A8322D` | 印章、重点、危险/代价提示 |
| 火橙 | `#D97A2B` | 火光、温度、计时警示（少量） |
| 夜蓝 | `#1B2430` | 夜色、江面、雪山/草地暗部 |

- 对比度：纸白/墨黑为主；朱砂只做强调，不用小字号长文；火橙不与纸白大面积相邻。
- 字体：标题得意黑，正文霞鹜文楷/思源宋体；`font-display: swap`；回退 `"Songti SC", "SimSun", serif`。
- 字号（1280×720 设计坐标）：标题约 72–96px，章节标题 40–48px，正文 22–26px，注释 16–18px；中文行高 1.7–1.9，字距 0.02–0.06em。
- 按钮：斜切/毛边造型（`clip-path`/`skew`），最小 44×44px；键盘 `:focus-visible` 必须可见；hover/active/disabled 四态齐全。

### 2.2 UI 组件库

至少做齐：

1. **标题画面**：游戏名、副标题、开始/继续、图鉴、设置；纸纹、印章、山形剪影。
2. **对话框**：姓名签、正文区、继续指示；配合打字机。
3. **选项卡**：2–3 个；hover/focus/已选/禁用；限时选项带倒计时环或条。
4. **章节标题卡**：章节号、标题、时间、地点；墨迹展开动画。
5. **史实注弹窗**：类型徽章（史实/回忆录/文学）、出处、“有不同说法”提示、可滚动、可关闭。
6. **图鉴**：7 张卡；锁定/解锁；解锁后可重读出处。
7. **结局卡**：五张精神卡 + 点名名单 + 数字。
8. **暂停菜单**：继续、设置、图鉴、回标题。
9. **设置面板**：文字速度、音量、静音、减少动效；持久化。
10. **HUD**：只放必要信息（章节进度/暂停），不要做成游戏化血条/分数。

做一个开发用组件预览页（如 `?ui=1`），一次看全所有组件在 1280×720、1920×1080、1366×768 下的状态。

### 2.3 程序化版画

- 层叠山形：3–5 层剪影，墨色透明度递减，边缘用折线/抖动，不要平滑渐变。
- 江面：横向白线 + 透视收束；夜间加少量高光。
- 雪粒/雾：粒子或噪声；预渲染到离屏 canvas，不要每帧铺满全屏噪声。
- 铁索：贝塞尔曲线 + 高光点；泸定关用。
- 纸纹/毛边：CSS 渐变/噪声或 SVG filter；缓存纹理，避免每帧重算。
- 印章：CSS/SVG 圆形或方形，朱砂底、反白字；只做点缀。
- 人物：剪影/半剪影，不做写实脸；姿态服务情绪。
- 随机性用 seeded RNG，保证同一场景每次一致；背景变化时只重绘一次。

### 步骤二出口

- [ ] 标题画面完成。
- [ ] 组件库在 1280×720、1920×1080、1366×768 三档不出界。
- [ ] 无外部图片；全部程序化/CSS/SVG。
- [ ] 断开网络/禁用 webfont 后，字体回退仍可读。
- [ ] 对比度、44px 热区、键盘焦点通过自检。
- [ ] 纸纹/粒子不拖慢帧率。

### 本步骤的坑

- 纸纹铺满全屏每帧重绘 → 卡。
- 字体文件太大 → 首屏慢；使用前核对授权，必要时子集化。
- 颜色散落 → 后面改主题要全文件搜十六进制。
- 只做标题不做组件 → 每个界面重新发明按钮/弹窗。
- 朱砂滥用 → 视觉疲劳、语义混乱。
- 忽略键盘焦点 → 键鼠体验差。
- 只做 hover 态 → 手机不可用。
- 把版画做成写实插画 → 风格跑偏、成本失控。

## 步骤三：VN 引擎（对应计划书 5）

**目标**：能完整播放一章对话，选项、旗标、史实注、存档都工作。

### 3.1 脚本节点

`story.js` 用扁平 `script` 数组，节点类型保持少而稳：

```js
{ type: 'line', speaker: '旁白', text: '……', bg: 'yudu_night', sfx: 'wind' }
{ type: 'choice', prompt: '……', timeout: 8, options: [
  { text: '……', set: { 'item.door': true }, cost: '……' }
]}
{ type: 'minigame', id: 'door', config: { duration: 75 } }
{ type: 'codex', id: 'yudu' }
{ type: 'end', next: 'map' }
```

- `scriptIndex` 进存档；刷新后从当前节点恢复。
- 剧情文本按纯文本渲染，用 `textContent`，不要 `innerHTML`；需要强调就拆成多个 line 或分段字段。
- 旗标命名空间：`item.*`、`trust`、`memory.*`、`choice.*`；在 `story.js` 顶部写一张旗标表。

### 3.2 打字机与推进

- 用 `requestAnimationFrame` + 累计时间逐字显示；不要每个字一个 `setInterval`。
- 文字速度四档：慢/正常/快/瞬显；设置持久化。
- 第一次点击/空格补全当前行，第二次推进；推进后加约 100ms 输入锁。
- 标点可加短停顿（句号/省略号），但不要让整章拖沓。
- 自动模式：按字数计算停留时间；遇到选项、小游戏、史实注自动停止。
- 跳过：只对已读章节开放；首次游玩不显示“跳过”，避免跳过关键史实注。
- 转场期间锁输入；`go()` 时清掉所有打字机定时器。

### 3.3 选项与旗标

- 每章 2–3 个选项，每个 2–3 个选项项；选项是取舍，不是知识问答。
- `set` 合并进 `flags`；`cost` 是一句可读的代价，结算时展示，不藏起来。
- 限时选项：`timeout` 秒 + 明确的 `defaultOption`；超时按默认项结算，记 `timedOut: true`，不能“免费”超时。
- 选择历史写入 `state.choices`：`{ chapter, nodeIndex, optionText, timedOut }`；遵义错误卡直接引用。
- 单一结局：旗标改变细节、台词、代价、点名名单，不生成分支结局树。

### 3.4 史实注与图鉴

- 首次遇到可自动弹窗；关闭后回到原节点，不丢进度。
- 弹窗期间暂停打字机、倒计时、小游戏计时。
- 内容固定四块：标题 / 类型（史实/回忆录/文学）/ 出处 / “有不同说法”提示（如适用）。
- 解锁写入 `state.codex` 并持久化；图鉴可从标题/暂停菜单进入。
- 锁定卡只显示“未解锁”，不剧透标题与内容。
- 7 张史实注必须全部可达；不能因章节裁剪丢掉。

### 3.5 暂停、设置、自动/跳过

- `Esc`/暂停按钮打开暂停菜单；暂停游戏计时与输入，音频可降为环境声。
- 设置：文字速度、音量、静音、减少动效；即时生效并持久化。
- 自动/跳过状态要在 UI 上可见，避免玩家不知道自己在自动播放。
- 从暂停菜单回标题前自动存档；回标题不丢已解锁图鉴。

### 步骤三出口

- [ ] 从标题进入，完整播放一章（建议序章或湘江）。
- [ ] 打字机/补全/推进/自动/跳过都正常。
- [ ] 选项写旗标；限时选项超时路径可复现。
- [ ] 史实注弹窗/解锁/图鉴/持久化正常。
- [ ] 暂停、设置、音量/文字速度持久化。
- [ ] 对话中途、选项处刷新都能恢复。
- [ ] 控制台无报错。

### 本步骤的坑

- `setInterval` 逐字 → 后台标签页漂移、切场景后还在跑。
- 多处绑定输入 → 一次点击跳两句。
- 跳过把选项/小游戏/史实注一起跳掉 → 状态损坏。
- `innerHTML` 渲染剧情 → 注入/排版问题；用 `textContent`。
- 旗标不持久化 → 刷新后选择失效。
- 超时默认项没有代价 → 玩家学会“挂机”。
- 弹窗不暂停计时 → 读史实注时选项超时。
- 自动模式在选项处不停 → 卡死或自动替玩家选。

## 步骤四：核心小游戏（4 关，对应计划书 6）

**目标**：核心 4 关可独立试玩；第 5 关可选；统一接口；失败只结算代价，不重开。

### 4.1 统一接口

```js
// minigames.js —— 每关实现同一契约
const game = {
  id: 'door',
  title: '门板',
  duration: 75,                 // 秒，60–90
  init(host, config) {},        // 建 DOM/Canvas、绑事件、初始化状态
  update(dt) {},                // dt 秒；推进计时/动画/物理
  draw(ctx) {},                 // 画到 Canvas（若该关用 Canvas）
  end() {                       // 只调用一次
    return {
      success: true,            // false 也要继续剧情
      cost: {},                 // 叙事代价
      flags: {},                // 写回 story 的旗标
      summary: '一句话结算'
    };
  }
};
```

- 引擎负责：进入时 `init`，每帧 `update(dt)` + `draw(ctx)`，时间到/完成时 `end()`，把结果交给 `result` 场景，再回剧情。
- 失败不重开：`success: false` 只产生代价；UI 不出现“重试”，最多“继续”。
- 页面隐藏时暂停计时；回来时不要一次性补算几十秒。
- 所有小游戏共用一套“限时分配”引擎：计时器、拖拽、配额、疲劳、网格、结算面板。先做共用件，再做 4 关配置（第 5 关可选）。

### 4.2 核心 4 关 + 可选第 5 关设计表

| 关卡 | 章节 | 核心操作 | 时间压力 | 失败代价 | 写回旗标（示例） |
|---|---|---|---|---|---|
| 门板 | 序章·于都 | 拖拽物品到门板/行囊，决定带什么；门板不可弃 | 天亮倒计时 60–90s | 少带某物/超重，后续对话与分粮受影响 | `item.*`、`load`、`dawn_left` |
| 弃物 | 第一章·湘江 | 拖拽“保留/放弃”；渡口配额 | 追兵/渡口关闭倒计时 | 放弃某物/人员，遵义错误卡引用 | `abandoned.*`、`regret`、`choice.xiangjiang.*` |
| 渡船 | 第三章·金沙江 | 调度船次、分配人员、安排船工休息 | 追兵计时 + 船工疲劳 | 部分人未渡/船工耗尽，终章数字变化 | `crossed.*`、`boatman_fatigue`、`trust` |
| 攀索 | 第四章·泸定 | 节奏/时机动作，沿铁索前进，22 个光点 | 火势/时间 | 光点熄灭（牺牲），不重开 | `lights_lost`、`memory.names` |
| 探路/分粮（可选） | 第五章·草地（完整版） | 网格探路 + 分粮/体力分配 | 体力/粮草 | 减员/迷路，终章被记住的名字变化 | `grain`、`health`、`memory.names` |

旗标名是示例，步骤零/五定稿后统一；不要一关一套命名。

### 4.3 每关规则要点

**门板（序章）**

- 门板占固定槽位，不可丢弃；玩家决定的是“还要带什么、怎么绑”。
- 物品有重量/体积；行囊有上限；天亮倒计时。
- 没有“全带走”解；超重会让行军变慢，少带会在后面缺东西。
- 结算展示带走了什么、留下了什么；写回 `item.*`，供后续分粮/对话引用。

**弃物（湘江）**

- 拖拽“保留/放弃”，在渡口配额与时间压力下做取舍。
- 重装备（含 X 光机等争议细节）必须舍弃；历史结局固定，不能“全救”。
- 结算把实际放弃项写进 `choice.xiangjiang.*`，遵义错误卡直接引用。
- 不做战斗；压力来自时间、配额和不可逆的舍弃。

**渡船（金沙江）**

- 玩家调度船次：每船容量、往返时间、船工疲劳、休息。
- 追兵计时推进；船工数量由前面累积的民心值决定（公式集中在一处，可调试、可解释）。
- 不能全员一次渡完；失败代价是少渡一批/船工耗尽，不是 Game Over。
- 不做“打追兵”；敌人只作为时间压力存在，不脸谱化。

**攀索（泸定）**

- Canvas 动作/节奏关：沿铁索前进，22 个光点代表 22 位勇士/名字。
- 操作尽量简单（点击/按住/左右），单手可完成；失败熄灭一个光点但继续。
- 不做血腥；光点熄灭用留白与名字被划掉表现。
- 22 勇士牺牲人数有不同说法，图鉴标注；游戏内不把牺牲做成分数。

**探路/分粮（草地，可选第 5 关）**

- 核心版不做这一关：草地只保留对话 + 分粮/让粮的资源选择。
- 网格 + 战争迷雾：探路、找方向、分配粮草/体力。
- 没有战斗；压力来自资源与减员。
- 结算写回 `grain`、`health`、`memory.names`；终章点名会读这些名字。
- 失败代价是减员/迷路，不是重开。

### 4.4 接入约定

- 小游戏结果只通过 `end()` 返回，不直接改 `story.js`、不直接跳章。
- 章节接入时先跑“成功路径”和“失败路径”各一次，确认代价能在后续剧情里看到。
- 开发期支持 `?minigame=door` 单独试玩；发布前可保留但隐藏。
- 每个小游戏首屏 5 秒内要能看懂怎么玩：用图形/手势提示，不要一大段说明。

### 步骤四出口

- [ ] 核心 4 关可独立试玩；第 5 关探路/分粮可选。
- [ ] 每关 60–90 秒。
- [ ] 键鼠 + 触摸都能完成；手机单手可玩。
- [ ] 失败路径继续剧情，代价可见、可写回。
- [ ] 结果旗标被后续章节消费。
- [ ] 切后台暂停；回来不跳秒。
- [ ] 控制台无报错，帧率稳定。

### 本步骤的坑

- 每关一套独立引擎 → 范围爆炸；先做共用件。
- 失败重开 → 违反“没有 Game Over”。
- 把牺牲做成分数/排行榜 → 违反情感尺度。
- 小游戏结果与固定历史冲突（例如湘江大胜）→ 红线。
- 只支持鼠标拖拽 → 手机不可用。
- 用 `setInterval` 计时 → 漂移；用 `rAF` delta。
- Canvas 命中区不按缩放换算 → 触摸偏移。
- 结果不写回 → 玩家觉得选择没意义。
- 规则说明太长 → 60–90 秒的关卡应在 5 秒内可上手。

## 步骤五：章节接入（对应计划书 7）

**目标**：七章按顺序接入，从头玩到尾；选择、代价、史实注、结局全部串起来。

### 5.1 逐章接入清单

每章都走同一套“进 → 玩 → 出 → 结算 → 史实注”：

1. **进**：章节标题卡（时间/地点）、前情、读取旗标。
2. **玩**：对话/选项/小游戏；规则提示简短；二周目可跳过提示。
3. **出**：结算面板，展示代价（不是分数）。
4. **结算**：写回旗标、民心值、记忆名单；自动存档。
5. **史实注**：解锁/弹窗；类型、出处、争议提示齐全。

接入顺序固定：序章 → 湘江 → 遵义 → 金沙江 → 泸定 → 草地 → 点名。

### 5.2 数据流

```text
选项/小游戏 → flags → 后续场景
民心值 trust → 金沙江船工数量
前两章选择 → 遵义错误卡
memory.names → 终章点名
codex 解锁 → 史实图鉴
```

- 公式集中在一处（如 `story.js` 顶部的 `RULES` 或 `engine.js` 的配置），不要散落在各章。
- 示例：`boatmen = clamp(1 + floor(trust / 2), 1, 3)`——仅为示例，步骤零/五校准；必须可解释、可在调试面板查看。
- 错误卡展示真实选择文本、后果、史实背景；不羞辱玩家、不虚构领导人点评。
- 遵义场景用旁白/会议文件/虚构基层人物呈现，不让真实领导人开口。
- 终章点名读取 `memory.names`，把玩家救下/记住/失去的名字逐个念出；数字必须有出处。

### 5.3 节奏预算

目标时长（首次游玩，步骤七实测校准）：

| 章节 | 目标 |
|---|---|
| 序章·于都 | 3 分钟 |
| 第一章·湘江 | 3.5 分钟 |
| 第二章·遵义 | 2 分钟 |
| 第三章·金沙江 | 3 分钟 |
| 第四章·泸定 | 3 分钟 |
| 第五章·草地 | 2.5 分钟 |
| 终章·点名 | 3 分钟 |
| 合计 | 20 分钟 |

超时裁剪顺序：草地 → 金沙江 → 遵义（改成纯对话）；保留序章/湘江/泸定/点名。

### 步骤五出口

- [ ] 从标题到点名无死路、无空场景。
- [ ] 7 张史实注全部可解锁。
- [ ] 结局有点名 + 数字 + 五张精神卡。
- [ ] 前两章选择能在遵义错误卡里看到。
- [ ] 民心值能影响金沙江船工数量。
- [ ] 首次完整通关 ≤ 20 分钟（至少测 3 次）。
- [ ] 章节边界与章节内都能存档/恢复。
- [ ] 没有任何选择让固定历史结局改变。

### 本步骤的坑

- 小游戏结果没接线 → 选择变假。
- 旗标太多太散 → 后面读不懂；命名空间 + 旗标表。
- 遵义变成讲课 → 用错误卡和对话，不要长篇旁白。
- 让真实领导人说话 → 红线。
- 结局说教 → 先给情感，再给五张卡；不要反过来。
- 超时后随机删内容 → 按裁剪顺序，保住情感主线。
- 章节锁太死 → 试玩卡住；顺序解锁，但图鉴可回看。

## 步骤六：音频与动效（对应计划书 8）

**目标**：不依赖任何音频文件的氛围层；转场与动效服务情绪，不抢戏。

### 6.1 Web Audio 合成

- 音频图：`AudioContext` → master gain → destination；环境声与音效分两条 bus，方便静音/压低。
- 风声：白噪声 → 低通滤波，LFO 缓慢调制截止频率；音量低、无突变。
- 水声：噪声 → 带通滤波 + 缓慢调制；金沙江/湘江可用。
- 鼓点：正弦/三角振荡器短促下滑 + 噪声瞬态；低频，少量。
- 口琴五音动机：三角/方波 + 轻微颤音；用五声音阶写一个**原创**短动机，不要用受版权保护的旋律。
- 首次 `pointerdown`/`keydown` 时创建或 `resume()` AudioContext；不要在页面加载时自动播放。
- 静音/音量持久化；切后台 `suspend()`，回来按需 `resume()`。
- 所有增益变化加短淡入淡出，避免爆音；master 限幅。

### 6.2 动效

- 转场：墨迹擦除、淡入淡出、章节卡展开；300–800ms，不要拖慢节奏。
- 闪白：只在必要处，低强度、低频（不超过 3Hz）；提供“减少动效”开关。
- 震动：短、小振幅；手机可关闭。
- 墨迹划名：终章核心演出；名字被划掉时配合留白/静音，不做血腥。
- 打字机光标、按钮按压、卡片 hover：轻微即可。
- `prefers-reduced-motion` 或设置开启时：关闭闪白/震动，缩短转场。

### 步骤六出口

- [ ] 仓库/ZIP 里没有音频文件。
- [ ] 首次点击后有声；无自动播放报错。
- [ ] 静音/音量持久化；切后台暂停。
- [ ] 无爆音、无削波；淡入淡出正常。
- [ ] 减少动效可用；闪白/震动可关。
- [ ] Chrome/Edge/Safari 各测一次。

### 本步骤的坑

- 页面加载就 `new AudioContext()` → 被浏览器挂起/报错。
- 每个音效新建 AudioContext → 资源泄漏、达到上限。
- 突然大音量 → 吓人、伤耳；所有音效加包络。
- 用现成歌曲/旋律 → 版权风险；写原创五音动机。
- 闪白过强/过频 → 光敏风险。
- 暂停菜单里音频还在响 → 玩家困惑；压低或只留环境声。
- 切后台回来不 `resume()` → 以为音频坏了。
- 动效每帧改布局 → 卡；用 transform/opacity。

## 步骤八：打包与交差（对应计划书 10）

**目标**：链接 + ZIP + 一页设计说明 + 3 分钟演示 + 制作名单/字体授权。

### 8.1 部署

- Cloudflare Pages：静态站点，构建命令留空，输出目录为根目录；可用 Git 集成或控制台拖拽上传。
- 备选 GitHub Pages：所有资源用相对路径，注意仓库子路径；不要以 `/` 开头。
- 部署后验证：无痕窗口、手机、HTTPS、控制台无报错、资源 404 检查。
- 不提交密钥、分析脚本、无关大文件；发布前打 tag/留 ZIP 副本。
- 不把“本地能跑”当作“线上能跑”；部署后再走一遍完整流程。

### 8.2 离线 ZIP

- 包含：`index.html`、`style.css`、`engine.js`、`story.js`、`minigames.js`、`art.js`、已授权字体（如打包）、`README`。
- 无任何外部请求；断网/飞行模式打开 `index.html` 仍可玩。
- 测试路径含空格/中文的 Windows 目录；解压到干净机器再试。
- `file://` 下 `localStorage` 可能受限：游戏要能继续，提示“本次不保存”，不能白屏。
- 检查体积；不要带源码映射/临时文件/未授权素材。

### 8.3 一页设计说明

控制在 1–2 页，能扫读：

1. **史实出处表**：7 条锚点、出处、类型（史实/回忆录/文学）、争议提示。
2. **精神对照表**：五条精神 → 对应机制 → 出现在哪一章。
3. **操作说明**：点击/空格推进、选项、小游戏、暂停、图鉴、设置、存档。
4. **虚构人物声明**：主角与虚构角色非史料人物。
5. **已知限制**：争议细节、未做内容、浏览器/存储限制。
6. **制作名单与字体授权**。

老师大概率只看 3 分钟，所以把“史实图鉴”和“结局五卡”放在显眼位置。

### 8.4 3 分钟演示

建议分镜：

| 时间 | 内容 |
|---|---|
| 0:00–0:20 | 标题 + 一句话概念（门板/两万五千里/20 分钟） |
| 0:20–1:10 | 序章·于都 + 门板小游戏 + 一个选择 |
| 1:10–2:00 | 湘江 + 弃物小游戏 + 代价 |
| 2:00–2:30 | 泸定 + 攀索（22 个光点） |
| 2:30–3:00 | 终章点名 + 数字 + 五张精神卡 + 图鉴/设计说明一闪 |

- 1080p 录制；配字幕；用游戏内合成音频或无声，不要用未授权音乐。
- 准备离线备份视频；现场网络不可靠时直接播本地文件。

### 8.5 交差清单

- [ ] 线上链接（HTTPS，无痕可开）。
